# Proposing the plan

The plan message: the table the user approves and the documents they keep or drop.

## Show it

1. Markdown, never in a code block. One row per unit: **what it produces, by its name, and
   why**, in one line. Detail belongs in the unit's report.
2. Use the plan's fixed words: a slice is a *tramo* in Spanish. Name documents by their
   name — the spec, the stories, the glossary — with a plain gloss beside, never instead.
3. Under the table declare **where it stops**, **what it leaves out** (*"coupon admin is
   F-009 and you did not ask for it"*), and what it covers beyond the minimum so the user
   can drop it. One line per skipped phase and why.
4. Standard work: one table and those declarations. Parallel groups: their id and model per
   unit, the work branch, and that the group stops once.
5. The autonomy offer, once, in one line.

## The documents

| Category | How |
|---|---|
| **Mandatory** | Declared, not offered: the work cannot continue without it |
| **Offered** | A line of the plan the user can drop, with what dropping it loses |
| **On request** | Absent unless the user asks |

- Mandatory documents are the ones each phase router declares mandatory.
- Offer with the loss, not the question: *"without it, this decision is re-argued in three
  months with no record of what was weighed"*.
- An existing document the change affects is kept current, never offered.
- Size sets ceremony, not the list: in standard work offer a document only when this work
  earns it, and say what earns it.

## Done when

Every row says what it produces and why; stops, exclusions and droppable extras are
declared; every document is declared mandatory or offered with its loss.
