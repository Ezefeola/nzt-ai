# The retro file

The file starts from `assets/retro.md`.

## Rules

1. **Headings stay as in the asset; everything else is in the person's language.**
2. **Plain words, except *For the method*:** its reader maintains the method, so it can name
   skills, references and the method's labels.
3. **Never a value from a session:** no key, output, file content or personal data the
   person did not choose to share. A secret is named by what it is, never by its value.
4. **Every proposal starts `proposed`.** Only the person moves it to `accepted`,
   `discarded` or `done`; a retro never does, not even in an earlier file.
5. **An empty section is one line** saying so.
6. **Severity:** high when it repeats or ended in rework or a silent failure, medium when
   it cost time, low when it was friction.
7. **Numbering runs through the whole file:** `R-01`, `R-02`… across sections.
